# 独立 FAR 精度版本、回归与统一重标协议 v1

本文件与同名YAML共同定义下一阶段；只完成协议定义，不表示已实现候选物理版本、封存执行锁或获准运行。旧G0c FAIL和诊断结果全部保留。

## 1. 实现边界

候选版本为`geometry19_v2_2_far_precision_v1`，不注册为默认profile，不编辑旧runtime、原燃烧室实现及其他冻结源码。仅FAR的xtol/rtol为1e-15，maxiter保持64；所有物理方程、map、热物性、求根区间、守恒门和目标域不变。

推荐明确的实现方式：校验原燃烧室源码哈希后，为原求解函数建立独立globals副本，其中仅brentq绑定到参数校验/覆写包装器；原模块的globals和SciPy不被修改。通过独立整机solver包装器显式注入这一燃烧室函数，其他组件solver原样透传。原后端已有`solver`依赖注入接口，可创建独立后端实例而不改旧注册表。必须测试原函数、模块及其他求根器未被污染，未知参数或接口漂移立即拒绝。

候选backend/model/bundle/context均有新身份。有效bundle绑定父bundle、候选实现/包装器源码及配置；新context绑定父context、新bundle、候选元数据和运行环境。不能只改结果中的model_version字符串而保留旧bundle/context。执行前封存实际实现哈希、环境、所有依赖、样本顺序及候选数据schema。

## 2. 固定阶段和预算

| 阶段 | 固定样本与比较 | 新整机求值上限 |
|---|---|---:|
| R1 实现一致性 | 原诊断根全部512点用候选C求值，与已封存B比较 | 512 |
| R2 跨根哨兵 | 其余32根每带取pair_index=1、sign=+1，共128点；原A及候选C各求值一次 | 256 |
| L 全量统一重标 | 原33根全部16,896点，全部由同一候选版本重新求值 | 16,896 |
| 合计 | 不含已经完成的1,024次诊断 | 17,664 |

R2选择只依赖冻结几何身份，不看性能、资格或改善幅度；pair_index=1按旧分组属于train。运行前写出确定的128点注册表，验证32根×4带各一点、与诊断根不重叠。R1同样保留原split，不转作独立泛化验证。

顺序严格为：候选实现/无物理测试→完整准备锁→单独授权R1/R2→R1封存并通过→R2原A完整封存并复现旧标签→R2候选C完整封存并通过→单独授权L→全量重标封存→判门。任何阶段失败停止，不加参数扫描、不补样本。

准备测试只允许合成函数/替身；禁止额外真实smoke调用。若需要运行含真实求值的既有回归测试，须先列出调用预算并另行批准，不能隐藏在17,664次预算之外。本预算内R1/R2为明确的物理回归。

## 3. 通过门

R1逐点精确比较solver、三性能、所有守恒残差、map状态、约束与目标域评估、坐标和split、所有资格标记。仅候选与诊断的版本/provenance及新增诊断元数据可以不同。不得以“结果差不多”替代B复现。

R2原A须复现旧账本上述字段；C不得出现新的solver/数值/physics-domain失败或原有效点失去资格。原/新三性能均有限正值时逐轴相对变化≤1e-6；原数据缺失明确记不可比，新数据缺失但原存在则失败。所有候选收敛点的能量残差必须≤1e-6 W，目标域转换完整报告。

L保持原坐标、正负配对和train/validation标记；132个128行分片、全账本和manifest封存后才判逐根256/64和逐带32/8有效点门。另要求无新增数值/domain失败、无原有效点失去资格、可比性能变化≤1e-6、收敛点能量闭合≤1e-6 W。记录不可比点、恢复点和域转换，不将恢复等同于训练资格。

这些无退化门是本次迁移的预注册风险控制，不是物理定律或独立工程认证。若被极接近边界的变化触发，先保留并报告失败，不现场放宽。即使有效训练点总数充足，仍需所有根通过；不以总数掩盖根级缺口。

## 4. 数据版本、防泄漏与恢复

- 新账本使用新目录；旧G0c、旧物理、目标注册表和诊断产物不可改写。
- L全部16,896点重新求值；不复用R1/R2/B标签节省预算，不只替换有改善的行。
- 同一新账本中model/bundle/context身份必须唯一；所有物理失败记录保留。
- 验证点永不进入training_candidate；原512点诊断已属于后选择审计，不宣称新的独立验证。
- 训练数据求值不读取目标内容、不调用旧代理模型或生成模型，不读confirmation。
- 每次整机调用先记持久化日志；完整分片恢复校验输入/实现/环境/输出哈希，半写或封存后缺片停止，不自动重放。
- 所有结果封存后才能评价总体数据门或做性能驱动决策；最终以拦截物理求值的重载验证证明零新增调用。

## 5. 目标和代理的跨版本边界

99个目标值及source选择不改。它们不参与本次标签生成或求根调参。本阶段也不重算99个source设计，故不能声称目标与新物理的跨版本兼容已被确认。进入目标闭环前另行审核。

已训练局部代理模型属于旧物理标签版本；不得因本根性能变化很小而直接认证其对全33根新物理有效。生成模型如果随后使用代理损失或代理筛选，先做独立兼容性审计或另批重训，不能混淆模型和标签身份。本阶段不修改或重训代理。

生成架构保持用户确认的方向：外部条件仅三个性能值；性能侧gate判根，再由相应局部expert生成。root_id仅用于训练监督/内部专家分发，medoid仅用于固定坐标解码，不加入外部条件。当前阶段只解决标签一致性，不训练gate/CFM。
